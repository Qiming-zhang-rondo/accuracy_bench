02 / 08
Problem

量化精度问题，难点不在“发现”，而在快速归因

同样一个坏输出，可能来自权重量化、激活量化、推理框架、并行通信、KV Cache，也可能只是低 margin 下的采样分叉。

没有分层证据时，只能反复换参数、换版本、重跑整模型。
1
端到端现象无法直接定位乱码、复读、答案漂移只是结果，不能说明根因在哪。
2
大模型不适合整模型双份常驻数百 B MoE、长 prompt、混合量化对显存和内存提出更高要求。
3
逐层误差不等于根因误差会沿网络传播，最低 cosine 层可能只是被上游污染。
4
不同执行栈难以公平比较必须统一 input_ids、position 与 sampler 前 logits 才能排除输入差异。
定位从模型级缩小到算子级
定界框架路径 vs 量化权重
复现输入与中间状态可追溯

Core Methods

关键不是多算几个指标，而是让指标对应可验证的判断

Δ

L1：首个发散层

定位误差开始显著放大的位置

同时观察绝对阈值与相邻层 delta，避免把“误差累积后的最低点”误判为起因。

Δcos(l) = cos(l) − cos(l−1)
↺

L2：反事实恢复

直接验证“替换它能否修复”

大子图用 Patch Recovery；旋转空间内部链路用 SelfRotErr / RotBErr；离散路由看 Flip Rate。

Recovery = (Ebase − Epatched) / Ebase
≋

Boundary：执行路径定界

区分框架、算子与权重问题

必现问题比较生成结果；偶现问题直接导入现场 input_ids 与 logits，避免重复 tokenize 和 ChatTemplate。

captured input_ids → Transformers replay
K

Logits：分岔敏感度

不把所有 Top-1 flip 都判成严重异常

联合 cosine、KL、Top-K overlap 与 Top-1/Top-2 margin，识别低 margin 排序翻转和持续性分岔。

高相似 + 小 margin flip ⇒ ranking-sensitive

Engineering for Large Models

围绕超大模型做工程化，而不是假设整模型都能常驻

MEMORY

分片加载与流式 Expert

模型骨架置于 meta device，按 shard 加载当前层；MoE expert 按路由命中流式读取或以压缩形态常驻，降低峰值占用。

PARALLEL

Ref / Quant 并发与长 Prefill TP

Ref、Quant 使用独立设备组并发 forward；GLM/DeepSeek 长 prefill 支持 query-parallel blockwise exact top-k。

FIDELITY
